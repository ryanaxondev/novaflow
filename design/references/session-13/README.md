# Session 13.2C Revision

This approved revision corrects the first high-fidelity reference iteration
without opening a new direction.

Differences from the first iteration:

- the operational grid is absent or extremely faint on white narrative surfaces,
- the Hero relationship-zone grid is approximately half as prominent,
- the Product workbench uses a quieter functional grid and a denser connected detail area,
- Onboarding guidance spans the workbench and relates directly to ownership and state summaries,
- Desktop Problem uses open content regions with partial rules and anchors rather than card shells,
- Solution uses one continuous workflow rail with light stage boundaries,
- Social Proof leads with the role-and-handoff model and presents the approved quote as an illustrative operating observation,
- the illustrative disclosure appears before the Social Proof narrative is interpreted,
- Mobile Product evidence is recomposed with full-width guidance, compact summaries, and approximately `12px` or larger Product labels,
- the contact sheet uses a quiet operational surface rather than a pervasive grid behind the references.

Grid localization rule:

```text
Narrative white surfaces:
Absent or extremely faint

Hero relationship zone:
Low opacity

Product workbench and Product canvas:
Visible only as a functional system aid

Problem and Solution:
Localized to relationship evidence

Benefits, Pricing, FAQ:
No pervasive grid

Final CTA:
Restrained low-contrast terminal grid
```

Problem regions must not use full enclosing card shells. Solution must read as
one connected system rather than three cards inside a larger card. Social Proof
must read as an illustrative operational scenario, not a customer testimonial.
Mobile must recompose the Product system instead of proportionally shrinking
the desktop workbench.

# Accessibility Validation

Calculated contrast ratios:

| Pair | Ratio | Intended role |
| --- | ---: | --- |
| `#F8FAFC` on `#0B1220` | `17.89:1` | Primary text on navy |
| `#FFFFFF` on `#2563EB` | `5.17:1` | Primary CTA text |
| `#111827` on `#FFFFFF` | `17.74:1` | Primary text on base |
| `#5B6474` on `#FFFFFF` | `5.97:1` | Secondary text on base |
| `#5B6474` on `#F7F9FC` | `5.66:1` | Muted text on subtle |
| `#5B6474` on `#EEF4FF` | `5.40:1` | Muted text on operational |
| `#2563EB` on `#FFFFFF` | `5.17:1` | Light-surface focus concept |
| `#22D3EE` on `#0B1220` | `10.36:1` | Dark-surface focus/state support |
| `#2563EB` on `#0B1220` | `3.62:1` | Mark and non-text active boundary on navy |
| `#60A5FA` on `#0B1220` | `7.36:1` | Flow line on navy |
| `#22D3EE` on `#FFFFFF` | `1.81:1` | Prohibited as required light-surface cue |
| `#60A5FA` on `#FFFFFF` | `2.54:1` | Decorative only on white |

Accessibility intent:

- Product state always includes labels, symbols, position, or shape in addition to color.
- Cyan is never the only state indicator.
- Decorative grids and connectors are intended to be `aria-hidden`.
- Approved marketing copy remains understandable without decorative visuals.
- Any unique Product relationship requires an accessible description in later implementation.
- Mobile labels remain readable at the represented 375 px width.
- Primary mobile targets are represented at a comfortable 44 px minimum.
- Light-surface focus may use Nova blue.
- Dark-surface focus may use Signal cyan with a non-color outline/shape treatment.
- No essential meaning depends on color alone.

# Known Limitations

- The references are static and do not demonstrate hover, focus, expanded FAQ, or menu-open interaction frames.
- Focus-ring contrast is calculated and conceptually represented, but not shown as a separate state sheet.
- The mobile reference uses 375 px; later implementation still requires 320 px validation.
- The desktop full-page image is a single review composition, not an exact Production-height requirement.
- Product panels use the approved minimal interface vocabulary and remain illustrative.
- The references do not prove browser accessibility-tree behavior because they are review images.
- The references do not prove Production performance because they are not Production assets.
- The references intentionally omit animation.
- The current approved mobile Navbar open-state model is described rather than redesigned.
